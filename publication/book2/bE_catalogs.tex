### Q_1_K_H ternary wire contract (the operator's H example, made exact)

For n = 256:

```
bytes  0–1   : FP16 scale               = 16 bits
bits      2–369: 232 trits, base-3 packed = ⌈232 × log2(3)⌉ = 368 bits
bits    370–383: 14 bits — covered by the 24 evenly-spread implicit-zero slots
                               (is_slot() Bresenham spread, slot weight = 0, never stored)
TOTAL = 384 bits = 48 bytes = 1.5000 BPW exact
```

Tail sizes (n ≠ 256): the shipped rule is `budget = ⌈1.5·n⌉ - 16`,
`k = ⌊budget / log2(3)⌋` trits and `z = n - k` implicit-zero slots, with `log2(3)`
rounded slightly **up** so `3^k ≤ 2^budget` holds by construction. The wire is
always exactly `⌈1.5·n/8⌉` bytes — **never inflate**. Below `n = 12` no room exists
for a 16-bit scale plus a trit, so the encoder writes the `Q_1` binary payload
(prefix-identical) zero-padded to the same wire and the decoder returns ±1.
Measured and pinned by `tests/test_ternary_tail.cpp` for `n = 1..512`.

## 1. Theorem 1 — Constant Memory (no KV bloat)

**Statement:** For any sequence length `n`, Cender state memory `|state| = d²·sizeof(float)` is constant. Transformers KV memory `|KV| = 2·n·d·sizeof(float)` is linear in `n`.

**Proof:**

1. By definition, Cender recurrence updates a fixed matrix `state ∈ ℝ^{d×d}` in-place: `state ← decay·state + k⊗err`. No term depends on `n`. Allocation is one `Tensor{d,d}` `include/quant/tensor.h`, never appended per token. Verified by code inspection `src/kda_attention.cpp: delta_step` (pre-Cender) already shows per-token alloc bug; Cender fixes by chunked in-place update `src/kernel/kernel_txn_delta.cpp` K1.

**QED.** Empirically: `bench_inference` tok/s vs `n` must be flat for Cender, decreasing for Transformers (Phase 14 gate).

**Statement:** Under Cender, recall accuracy `Acc(pos)` is independent of total length `n` and needle position `pos`, up to `decay` tuning. Under Transformers, `Acc(pos)` is U-shaped and degrades with `n`.

# Model manifest (`SolIDX`) — reserved format specification

Status: **reserved, documented, not implemented.** No engine reader or writer consumes this
format yet. The magic is specified here so that the first model-packaging consumer implements
one format instead of inventing a second meaning for the engine's `.idx` magic.

## Why this file exists

Two different identities were conflated during the 2026-11-12 rename wave:

- **Engine wire identity** — the `.idx` integrity index. It belongs to the engine, so its magic
  is `Transformers-FusionIDX` (current, 22 bytes) with `TransCenderIDX` as the accepted legacy
  alias (15 bytes, "formerly known as").
- **Model identity** — the artifact being trained or fine-tuned. The ruler model is
  `sol-4-flash` ("Sol 4 Flash"). A model name is not an engine name.

`SolIDX` is therefore **not** an engine `.idx` magic. It is reserved for a model manifest: a
small envelope that describes a packaged Sol model and its tensor inventory. The engine's
`QuantIDXReader` must reject `SolIDX` (regression: `tests/test_sha256_corrupt.cpp`, Test 8).

## Legacy names

`InNova` and `InNovaIDX` are **legacy names** from the pre-2026-11-12 project era:

- `InNova` was the model family that became `Sol`; the trained ruler model is now `sol-4-flash`
  ("Sol 4 Flash").
- `InNovaIDX` was the old wire magic. It became `SolIDX` during the 2026-11-12 rename wave, and
  D-30 retired the wire-magic half: `InNovaIDX` is rejected by the engine `.idx` reader and is
  never a current identifier.

Neither name is current. They are kept here only so that historical documents and old files can
be identified without ambiguity.

## Wire layout

All integers are little-endian.

| Offset | Size | Field | Value |
|---|---|---|---|
| 0 | 7 | `magic` | ASCII `SolIDX` followed by one NUL byte (`53 6F 6C 49 44 58 00`) |
| 7 | 4 | `version` | Manifest envelope version; `1` for this specification |
| 11 | 8 | `json_length` | Byte length of the UTF-8 JSON body |
| 19 | `json_length` | `body` | UTF-8 JSON object, no trailing NUL |

Minimum valid file: 19 bytes with an empty body is **not** valid; `json_length` must be at
least 2 (`{}`) and at most 16 MiB. A reader must validate `json_length` against the actual file
size before allocating or parsing.

## JSON body (version 1)

```json
{
  "model_id": "sol-4-flash",
  "display_name": "Sol 4 Flash",
  "manifest_version": 1,
  "created_utc": "2026-11-13T00:00:00Z",
  "engine": {
    "name": "Transformers-Fusion",
    "min_version": "0.1.0"
  },
  "tensors": [
    {
      "name": "model.layers.0.self_attn.q_proj.weight",
      "format": "Q_4",
      "bytes": 123456,
      "sha256": "64 lowercase hex characters"
    }
  ]
}
```

Required fields:

- `model_id` — must match `^sol-[a-z0-9][a-z0-9.-]*$`; the current ruler model is
  `sol-4-flash`.
- `display_name` — human-readable name, `Sol 4 Flash` for the current model.
- `manifest_version` — `1`.
- `tensors` — array of objects, each with a unique `name`, a registered format id in `format`,
  a non-negative `bytes` count and a 64-character lowercase `sha256`.

Optional fields: `created_utc`, `engine`, and any namespaced extension object. Unknown fields
must be ignored by a version-1 reader.

## D-09 · M-tier encoder (SUPERSEDED by D-32 on 2026-11-13)

**Original rule (historical, no longer the shipped layout):** M tier = base layout +
1 refinement byte per 32 weights, carrying 4 × 2-bit sub-block scale multipliers
{×0.75, ×1.0, ×1.25, ×1.5} — engine-agnostic, provably +0.25 BPW exact.

**Shipped rule (`DECISIONS.md` D-32, `block_codec.cpp:2649 tier_refine_layout`):** the
refinement region carries **signed additive per-span DC corrections**, not multiplicative
gains. Plain spans are 8 weights with a 2-bit q; GRP spans are 32 weights with an 8-bit
q. A multiplicative gain cannot express a DC offset at all, and the dominant residual of
a global-scale codec is exactly that offset; additive corrections dominate at identical
byte cost and make `q = 0` bit-identical to the base decode, which turns
`NMSE(L) ≥ NMSE(M) ≥ NMSE(H)` into a construction guarantee.

The D-09 acceptance gate was kept and strengthened: the shipped test measures **NMSE**
(not PSNR) with strict `M < L` everywhere, strict `H < M` for `b < 24`, and aggregate
strictness at every rung/family on 4 fuzz distributions + trained real weights
(`tests/test_tier_order.cpp`, 433 lines). The only allowance is per-case `H == M` ties
at `b = 24`, a proven FP32-output floor (D-32).

## D-10 · Ternary tail policy (design decision; shipped form noted 2026-11-14)

**Rule:** for block sizes where the exact-1.50 ternary layout doesn't decompose
(cleanly), the encoder NEVER inflates: it drops to the largest tier that fits the
name's wire budget exactly (ternary → M → L, per-size). Same policy for every
rewired format: budget guard pattern of `quant_grp16:879-884` (a real budget test,
never the `has_d = (n >= 8)` non-test that caused the quant_6k overrun).

**Shipped form (`Q_1_K_H`, D-32 / `LADDER.md` §ternary tail):** the tail rule is
`budget = ⌈1.5·n⌉ - 16`, `k = ⌊budget / log2(3)⌋` trits, `z = n - k` implicit-zero
slots, with `log2(3)` rounded slightly **up** so `3^k ≤ 2^budget` holds by
construction. No M-tier fallback is ever needed: the wire is exactly
`⌈1.5·n/8⌉` bytes for every `n = 1..512` (pinned by `tests/test_ternary_tail.cpp`).
Below `n = 12` a 16-bit scale plus a trit cannot fit, so the encoder writes the
`Q_1` binary payload (prefix-identical) zero-padded to the same wire; the decoder
returns ±1. That is the L tier of this ladder, i.e. the same never-inflate policy.
